# T999 LAN USB

ระบบเจ้ามือหวยแบบ Offline ผ่าน LAN + USB

## แนวคิดหลัก

ระบบนี้ไม่ใช่เว็บไซต์ออนไลน์  
ไม่ต้องใช้ Hosting  
ไม่ต้องใช้อินเทอร์เน็ต

ระบบทำงานแบบ:

- Master 1 เครื่อง
- Subkey หลายเครื่อง
- เชื่อมต่อกันผ่าน LAN / Switch Hub / สาย LAN
- โปรแกรมและข้อมูลหลักอยู่ใน USB / External SSD
- เครื่อง Master เป็นตัวรัน Server กลาง
- เครื่อง Subkey เปิดเข้ามาผ่าน IP ของเครื่อง Master

## หลักการใช้งานจริง

เสียบ USB ที่เครื่อง Master แล้วรันโปรแกรมจาก USB

ตัวอย่าง:

```text
USB Drive
└── t999-lan-usb/
    ├── README.md
    ├── server.js
    ├── master/
    ├── subkey/
    ├── data/
    ├── queue/
    ├── backup-usb/
    └── docs/
```

## Master

Master คือศูนย์กลางของระบบ

หน้าที่ของ Master:

- รับข้อมูลจาก Subkey แบบ real-time
- เห็นยอดรวมทั้งหมด
- เห็นยอดแยกเลข
- เห็นเลขเกิน limit
- แก้ไขใบโพยที่เก็บเข้าแฟ้มแล้ว
- จัดเรียงใบ
- เปลี่ยนเลขที่ใบ
- เพิ่ม / ลบ / แก้รายการ
- ทำโพยส่งนอก
- ตรวจรางวัล
- สรุปบัญชี 2 ฝั่ง

## Subkey

Subkey เป็นเครื่องคีย์เท่านั้น

หน้าที่ของ Subkey:

- เลือกเอเยนต์
- ใส่เลขที่ใบ ถ้ามี
- คีย์รายการจากโพย
- ตรวจรายการในใบปัจจุบัน
- กด “เก็บใบ”
- หลังเก็บใบแล้ว Subkey ล้างหน้าจอเพื่อคีย์ใบใหม่

Subkey ไม่ทำ:

- ตัดเลข
- ส่งออก
- ตรวจรางวัล
- สรุปยอดใหญ่
- รายงานกำไรขาดทุน
- จัดเรียงใบ
- แก้ใบเก่าหลังเก็บใบแล้ว

## กฎใบโพย

- 1 โพย = 1 ใบ
- ต้องเลือกเอเยนต์
- ไม่จำเป็นต้องใส่ชื่อลูกค้า
- เลขที่ใบใส่ได้ ถ้ามี
- ถ้าไม่มีเลขที่ใบ Master สามารถจัดเรียงภายหลังได้

## กฎการแก้ไข

### ฝั่ง Subkey

Subkey แก้ได้เฉพาะใบปัจจุบันที่ยังไม่ได้กด “เก็บใบ”

เมื่อกด “เก็บใบ” แล้ว:

- ใบถูกส่งเข้า Master
- Subkey แก้ใบนั้นไม่ได้อีก
- ถ้าผิด ให้ Master เป็นคนแก้

### ฝั่ง Master

Master แก้ใบที่เก็บเข้าระบบแล้วได้ เช่น:

- แก้เลขที่ใบ
- แก้รายการ
- เพิ่มรายการ
- ลบรายการ
- จัดเรียงใบ

## ระบบส่งออก / แทงออก

ระบบต้องเห็นเลขเกินแบบ real-time

Master ต้องเห็น:

- เลขไหนเกิน
- เกินเท่าไหร่
- เคยส่งออกไปแล้วเท่าไหร่
- ถ้ามีโพยเข้าเพิ่ม ต้องเห็นยอดเกินเพิ่มทันที

ในระบบหลังบ้านสามารถเรียก “ตัดเลข / ส่งออก” ได้  
แต่ในเอกสารที่พิมพ์ออกมา ห้ามใช้คำว่า “ตัดเลข”

ให้ใช้คำเช่น:

- ส่งนอก
- ส่งเจ้า A
- โพยส่ง
- ใบส่ง

## บัญชี 2 ฝั่ง

ระบบต้องมี 2 บัญชีแยกกันชัดเจน

### บัญชีที่ 1: ยอดรวมทั้งหมด

ใช้สำหรับ:

- สรุปยอดรวมงวด
- สรุปยอดเอเยนต์
- ตรวจรางวัล
- คำนวณกำไร/ขาดทุนจากโพยทั้งหมด

### บัญชีที่ 2: ยอดส่งออก / ส่งนอก

ใช้สำหรับ:

- รู้ว่าส่งเลขอะไรออกไปบ้าง
- คำนวณผลได้/เสียของยอดส่งออก
- ทำรายงานส่งออก
- พิมพ์โพยส่ง

## กฎสำคัญของบัญชี

ห้ามเอายอดส่งออกไปลบกับยอดรวมหลักโดยอัตโนมัติ  
เพราะเป็นคนละบัญชี

## โหมดรับโพย

ระบบต้องรองรับ 2 โหมดตั้งแต่แรก

### 1. Paper Mode

วิธีเดิม:

- คนรับรูปจาก LINE
- ปริ้นออกมาเป็นกระดาษ
- แจกให้ Subkey คีย์

### 2. Image Queue Mode

โหมดเสริม:

- รับรูปโพยจาก LINE
- เอารูปเข้า Queue
- เลือกเอเยนต์
- ส่งคิวรูปให้ Subkey
- Subkey ดูรูปบนจอแล้วคีย์
- ไม่ต้องปริ้นกระดาษ
- เก็บรูปต้นฉบับไว้ตรวจสอบได้

## LINE / LIFF ในอนาคต

ต้องออกแบบไว้ตั้งแต่ต้น แต่ยังไม่ให้เชื่อมตรงกับ Master/Subkey แบบเสี่ยง

แนวทาง:

- LINE / LIFF ส่งเข้าชั้นกลาง Queue
- Master/Subkey ดึงจาก Queue อย่างปลอดภัย
- LIFF ในอนาคตอาจส่งได้ทั้งรูปโพยและ structured slip

ตัวอย่าง structured slip ในอนาคต:

```json
{
  "agentId": "A001",
  "paperNo": "001",
  "market": "thai",
  "items": []
}
```

## Parser สำคัญ

กฎที่ล็อกไว้แล้ว:

```text
บ52=100x100
```

หมายถึง:

```text
52 บน 100
25 บน 100
```

ไม่ใช่:

```text
52 บน 100 ล่าง 100
```

## หน้าจอ Subkey

Subkey มีแถบบน:

- เอเยนต์
- เลขที่ใบ
- โหมด Paper / Image Queue
- สถานะเชื่อมต่อ
- เครื่องที่ / ผู้คีย์

โซนหลัก:

- โซนรูปโพย
- โซนรายการเข้า
- โซนปุ่มคำสั่ง / คีย์ลัด

ไม่ต้องมีรูปคีย์บอร์ดเต็มจอ

## การแสดงรายการ

ต้องแตกเป็นแถวจริง เช่น:

```text
25   100   100
52   100   100
```

ไม่รวมเป็น:

```text
25/52
```
